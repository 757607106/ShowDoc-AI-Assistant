# 知识库与知识评审对齐记录

更新日期：2026-11-16（Asia/Shanghai）。本轮按官方控制台与 ContextDB 0.0.9 DATA API 对齐知识库、知识图谱、知识 Wiki、知识评审及策略与模板，继续使用项目现有 TDesign 组件、卡片与画布，不引入另一套前端框架。

一个采集范围绑定一个真实知识库 ID。创建弹窗默认选择 Wiki 编译、关闭知识评审；不再强制写入 `high_threshold=0.85`、重写开关或重写稿自动入库策略。评审策略从服务端读取，修改时只提交已编辑字段。`0.85` 是官方页面本次显示的配置示例，不作为平台默认值。

创建弹窗保留官方“创建后不可切换编译模式。”说明；知识库创建后不允许转换 Wiki 模式。对于非 Wiki 库，后端允许通过官方知识库更新接口调整 `graph_enabled`，不再将这种变化判为非法模式漂移；当前界面不新增未经控制台实查确认的图谱开关入口。仅向原生创建接口传入名称时，图谱与评审开关分别沿用官方的开启、关闭默认语义；这与创建弹窗明确选择 Wiki 的行为不同。

## 实际数据流

选择真实 ContextDB 知识库 → 爬虫采集／上传 → 保存原件 → 必要的送审格式转换 → 官方评审或直接入库 → 正式正文 → 所选模式的派生内容 → 现有 Agent 检索并核对来源。

- 零编译：正式正文解析、切片与检索。
- 图谱编译：保留正式正文检索，另提供实体、关系及其来源切片。
- Wiki 编译：保留正式正文检索，另整理主题页、章节与页面关系。

正式正文可能是原文、已接受的 AI 重写稿或人工提交的完整正文。`accept_rewrite` 使用服务端已经生成的重写稿，或通过 `edited_content` 提交人工编辑后的完整正文，不只提交摘要。评审动作受理后仍需等待正文入库及相关编译完成。处理结果不会回写采集原件或外部来源。

## Markdown 合集的核对

用户记忆正确：`crawlers/base.py` 的旧 CLI 导出流程先保存逐篇 Markdown，再生成完整合集。平台 Worker 使用 `source_only=True`，保存来源及逐篇清单，不执行旧导出与本地切片流程。

本轮复用已经存在的单篇 Markdown；仅在开启评审且源格式为 HTML 时，使用现有 Docling 转换器生成送审 Markdown，不运行本地切片、评分或第二套评审。历史 `content_format=markdown` 的采集产物保留格式标记，避免因原始来源是 HTML 而重复解析。合集作为离线导出保留，不与单篇资料重复入库；本轮没有为平台新增一套合集生成器。

开启评审时 TXT、Markdown、PDF、DOC、DOCX 直接送审，不能生成可评审正文或不支持评审的格式阻止提交并显示原因。关闭评审时上传官方支持的原件，不把上传成功描述为已评审。普通上传可用 `review_enabled` 覆盖知识库默认值，格式校验与 HTML 转换按本次选择执行；分片初始化不支持该字段，遇到时明确拒绝，不静默忽略。

采集以及通过资料采集入口上传的原件和快照继续保留在本地。知识库文件页的普通或分片直传由 ContextDB 管理原件，不声明具有本地永久归档。本轮不删除既有来源归档，也不删除或重建云端知识库、文档、图谱数据。

## 入口及生命周期

知识库列表与详情以官方 `knowledge_base_id` 和名称为权威，不再要求用户额外创建或关联 Wiki 业务空间。旧 Wiki、图谱库按各自真实 ID 独立保留，旧地址只做兼容跳转。

新同步任务仅保存一个目标 ID 与模式；旧未执行双目标任务被阻止，需按明确单库目标重新提交。非 Wiki 库的图谱开关改变后，已有排队任务、来源映射和官方文档 ID 仍可沿用，不因开关变化重复上传；已有文档的图谱补建仍需显式调用官方处理接口。来源原件 hash、转换指纹、提交正文 hash 分开记录。同源未变化会跳过，即使后来调整评审开关，也不会覆盖已采纳的人工稿。来源变化使用官方更新与评审，不新增本地更新审批队列。

切换运行实例前，应先停止接收新任务并等待旧 Worker 正在执行的任务收尾，再更新并重启应用和 Worker。新版 Worker 遇到尚未投递的旧双目标任务会保留任务参数、来源和回执，标记为取消，提示用户选择一个知识库重提；不会自动将旧任务改投其他 ID。本轮没有执行生产实例切换。

重命名调用官方 PUT，并回读名称；库 ID 与历史引用不变。删除先检查文档、采集、同步和有效分片会话，通过同库锁阻止新的写入竞态。非空库需先清理并等待官方异步处理；超时保持待确认，403 不当作不存在。已删除或缺失的库不会自动重建，也不会绑定同名新 ID。来源归档及历史回执保留，删除后的历史任务可读，重试写入受阻。

文件管理使用官方上传／分片／更新、元数据、切片、预览、下载／批量下载、失败重试及删除接口。文件树使用官方 `tree_version`，非空目录递归删除需显式确认。节点操作携带当前库上下文，在同库写锁内通过官方节点读取核实所选节点及移动目标的归属，再一次转发原批次，保留官方祖先分组与逐项结果；归属无法确认时不执行该批次。Wiki 与图谱继续使用现有官方能力；没有增加本地编译器、图谱引擎或 Agent 框架。

分片上传记录仅保存票据 hash；工作空间成员之间不能使用对方的本地上传会话。完成接口返回的文档 ID 是最终权威；完成请求结果不明确时不自动重试或取消。官方票据有效期为一小时，过期记录不永久阻止删库，官方文档是否清空仍须核对。

## 官方页面与 DATA API 的边界

- 知识库文件页、知识图谱的查看图谱／实体管理、知识 Wiki 的阅读／编译记录，以及知识评审的列表／详情分别沿用现有组件对齐官方排版和文案。图谱复用 `ContextDBGraphCanvas.vue`，不再依赖 `wikiGraphLayout.ts`。
- 策略与模板使用独立页面。评审策略只展示官方页面的四项：启用知识评审、重写文件自动入库、启用知识重写、自动入库阈值；冲突检测和评审轮次仍属于官方 API 能力，不增加为本页的可见控件，也不随保存覆盖。
- 重写模板使用官方列表、详情、创建、更新及删除接口；编辑前读取详情，列表或详情请求迟到时不能覆盖其他知识库。保存和删除具有直接权限门禁及重复提交保护；“AI帮写”没有已确认的对应 DATA API，不增加模拟接口或第二套 Agent。
- 官方控制台可以切换知识评审成员，但公开 DATA 0.0.9 列表没有 `user_id`、`member_id`、`only_mine` 参数，也没有切换调用身份的接口。项目只展示当前 API Key 所属成员并禁用切换；“我的评审”不附知识库过滤，“按知识库查看”传 `knowledge_base_id`。不能用无效参数宣称跨成员筛选已生效。
- 评审动作按官方生命周期与权限启用；批量动作、批量删除评审记录分别使用 POST、DELETE。单项资源不可用不阻止其他可处理评审；拒绝文档、撤回内容和删除评审记录的语义分别展示。

策略和重写模板更新接口没有正文编辑那样的版本 CAS。界面只提交修改字段，保存前回读发现同字段变更时保留草稿并拒绝覆盖；这不能消除回读至写入之间的并发窗口。
